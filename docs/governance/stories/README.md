# Development Stories

Story files turn approved plans into small implementation units. Use one story
per independently testable change.

## Story Naming

Use:

```text
YYYY-MM-DD-short-slug.md
```

Example:

```text
2026-07-03-frontier-push-profile-schema.md
```

## Story Requirements

Each story must state:

- intent,
- product boundary impact,
- files expected to change,
- data read/write behavior,
- tests or fixtures,
- rollback plan,
- review checklist.

If a story grows beyond one focused change, split it before implementation.
